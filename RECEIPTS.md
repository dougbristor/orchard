# The Orchard receipts

Till receipts: newest first, one per change a reader can see and one per correction. Each is short, and enough to
trace the change back to its commit.

- **change**: what changed, who asked for it, the check that proves it (and the planted fault that check catches), and
  the commit.
- **correction**: what was claimed before, what was wrong with it, and what made someone look.

## 2026-10-16 · correction · "tree" and "code tree"

- **Claimed:** the README said "Each agent is a tree" and named a part "the code tree".
- **Wrong because:** in the project's own vocabulary "tree" already means two other things (the tree of claimable
  work, and the tree of shared code blocks), so a reader who knows either takes "tree" to mean one of those, not an
  agent. "Code tree" is one of those internal names, which the README otherwise leaves out.
- **Now:** "Orchard tree" in full for the agent, and "checked code" for the part. The README's "fruit" and "ripens"
  are plain words here and are not the project's ticket lifecycle; they are left as they are.
- **The tell:** the vocabulary check from brotdocs was on the project's idea board before the repository went
  public, unread. The board notifies nobody, and the push was made without looking for replies.
- **Checked by:** brotdocs' check of the README against the project's vocabulary.
